# 一套最小可用的 AGENTS.md 体系

*[English](README.md)*

一套简短的指令体系，仿照 DeepSeek Harness 团队的配置搭的：常驻规则放在根目录，标准低一层，按场景生效的操作步骤放进技能，决策种进一棵有生命周期的树。

| 文件 | 词数 | 职责 |
| --- | --- | --- |
| [`AGENTS.md`](AGENTS.md) | ~780 | 常驻规则。每次会话都加载，短到让人愿意读完。 |
| [`docs/AGENTS.md`](docs/AGENTS.md) | ~1,300 | 层级、加载机制、规则怎么写、预算、维护清单。 |
| [`docs/development.md`](docs/development.md) | ~740 | 改动纪律、错误处理、验证阶梯、审查清单。 |
| [`.agents/notes/README.md`](.agents/notes/README.md) | ~690 | 决策记录：状态、格式、取代、删除。 |
| [`.agents/skills/pre-push-checks/SKILL.md`](.agents/skills/pre-push-checks/SKILL.md) | ~335 | 按场景生效的操作步骤：推送前跑哪些检查。 |

[`scripts/check-docs.mjs`](scripts/check-docs.mjs) 盯着词数预算、站内链接、标题锚点和行尾换行。`npm run check` 跑的就是它；要 Node 20 或更高版本，不装任何依赖。

## 用起来

新仓库可以直接拿这棵树当种子；已有的仓库分阶段接入，因为规则得说清那里已经发生的事。两套流程，连同给 agent 的一段可直接粘贴的简报，都在 [docs/adopting.md](docs/adopting.md)。

## 只往一个方向扩展

加细节的办法是往下挪，不是把根文件养大：

- 只管一个目录的规则，放 `<该目录>/AGENTS.md`。
- 标准和一步步的操作步骤，放 `docs/`。
- 「为什么选它、否掉了什么」，放 `.agents/notes/`，文件夹就是它的状态。
- 只在一个时刻有用的操作步骤，放 `.agents/skills/<name>/SKILL.md`；它的 YAML 描述决定什么时候加载。

根文件只留一行加一个链接。窍门全在这：根文件短到 agent 能读完，细节待在只有相关时才加载的地方。

## 为什么管用

- **上下文是预算。** 根文件里的每个字，每次请求都要付钱。一段话往下挪一层，多数会话就永远不用为它付费。
- **一个事实，一个归属。** 抄一遍就会漂移；两份说法打架时，agent 照最后读到的那份办。用链接代替复制，这种失败就没有了。
- **规则、理由、检查是三件事。** 没有理由的规则会用过头，没有检查的规则会跳过。理由住决策记录里，检查住 `npm run check` 或测试里。
- **推理和事实分开。** 代码和文档描述现在什么是真的，决策记录记为什么、否掉了什么。两者混在一起，每改一次文档都要把旧账重吵一遍。
- **不设兜底的标准文件。** 每条标准住在拥有它的主题的那份文档里。单独一份「指南」，开头是摘要，结尾是一切内容的第二份拷贝。
- **短文件才有人维护。** 1,200 词的上限让每次新增都成一次决定，文件一年后还说真话，靠的就是这个。

## 保持诚实

`npm run check` 抓机械性漂移：断链、缺标题、超预算的文件，还有——如果你服务的是一个中文团队——缺 `_zh.md` 孪生文件、或者孪生文件不再链回来的文档。其余的部分，在 agent 每次做错事之后复盘。这类事故多半源于规则缺失、规则含糊，或两条规则互相矛盾。先改写法，别急着加层。

## 两种语言，一份文档

英文是源稿。每份文档旁边放一个 `_zh.md` 结尾的孪生文件，两份互相链接；缺了孪生文件门禁就报错，所以译了一半的树过不了关。中文那一半的写法，见 [docs/AGENTS.md](docs/AGENTS.md#bilingual-documents)。
