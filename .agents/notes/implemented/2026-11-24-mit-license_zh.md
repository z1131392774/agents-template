# 决策记录：以 MIT 许可证发布

*[English](2026-11-24-mit-license.md)*

Status: implemented

## 问题

模板已经公开，却没有任何许可证。按默认版权，读者只能克隆，不能复用，README 里「用起来」那一节就成了一纸法律上做不到的邀请。这棵树是从 DeepSeek Harness 提取的，而它本身以 MIT 发布；再挑一个别的许可证，抄来的文字在出处上就自相矛盾了。

## 决定

仓库采用 MIT，直接从 DeepSeek Harness 的 `LICENSE` 复制，并保留它的 `Copyright (c) 2026 DeepSeek` 声明。MIT 是仍然保留署名要求的常见许可证里最宽松的一种，也正是来源仓库已经给出的条款。

README 用一行写明许可证，并指出 DeepSeek Harness 是来源仓库，中英两半都写。读者不必再翻第二份文件就知道这些文字从哪来。

## 考虑过的替代方案

- **不要许可证。** 公开但没有许可证的仓库仍然是「保留所有权利」；想采用的人可以读这份模板，却不能合法复用，公开就失去了意义。
- **Apache-2.0。** 与来源兼容，还附带明确的专利授权，但要额外加一个 `NOTICE` 文件和逐文件变更声明——对一份只有五个文档的模板来说太重了。
- **CC0 或 Unlicense。** 放弃署名要求，比来源允许转授的更宽松；MIT 要求版权声明随来自 DeepSeek 的文本一起传播。
- **BSD-2-Clause。** 授权几乎与 MIT 相同，只是署名措辞不同；没有理由偏离来源已经选定的文本。
- **给这个仓库另立一套许可证。** 等于给一份文本出自同一个 MIT 来源的树再加上第二套条款，没有任何收益。

## 后果

拷贝和 fork 必须保留 MIT 声明。文档门禁不受影响，因为 `LICENSE` 不是 Markdown 文档，不需要翻译。GitHub 现在会在仓库页头识别并显示许可证。
